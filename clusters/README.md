# clusters/ — what Argo CD deploys where

Argo CD runs on C3 (the hub) and deploys to every cluster from here. Each directory
`clusters/<dir>/` becomes one Application named `<dir>-root`, generated by the `roots`
ApplicationSet in `c3/roots.yaml`. That Application applies the Argo CD objects in the
directory, never workloads directly, to the hub.

| Directory | Holds | Example |
|---|---|---|
| `all/` | ApplicationSets that target every cluster labelled `a-demo.io/fleet: "true"` | Cilium, canary |
| `c1/`, `c2/` | Applications for one cluster only (`destination.name: c1`) | GPU Operator (B3), models (B7) |
| `c3/` | Hub-only objects | Argo CD itself, `roots`, the `c3` cluster registration |

The manifests and Helm values themselves live under `platform/`, `inference/`, `tenancy/`, etc.
`clusters/` only says *what goes where*.

Cluster names (`c1`, `c2`, `c3`) come from Argo CD cluster Secrets. `c3` is registered from Git
(`c3/cluster-c3.yaml`). `c1` and `c2` hold tokens, so `infra/ansible/gitops.yml` creates them.

Check the fleet:

```bash
kubectl --context c3 -n argocd get applications
for c in c1 c2 c3; do echo -n "$c: "; kubectl --context $c -n a-demo-canary get cm gitops-canary -o jsonpath='{.data.message}'; echo; done
```
